# AXION 暂以“编译型编程语言”的形态出道



### 在传统编程里，我的思维被语言绑架：  
————————————————————————————————————————————————————
 
C指针被信奉为不可动摇的底层真理   
js、python...告诉我区分值和引用是不可逾越的编程法则  
java让我把世界抽象为类与接口，并规定我只能一切从class开始  
rust让我做好不小心写个a就会失去所有权的心理准备    
...  

$\color{#008000}{\text{——我学得越多，越觉得自己在成长，可实际上只是在熟练地自我驯化，甚至引以为傲 }}$   


<br>

我必须把自己正常的世界观扭曲重构，再辅以各种设计模式、编程技巧、层层封装....最终强行塞进某个语言允许的框架里  
而细思极恐的是，一半以上的编程负担都源自于语言本身的设计缺陷  

$\color{#008000}{\text{——我用字符和回车筑起殿堂，却再也寻不见出去的方向;  我失去的不止是效率，更是作为一名思想者的尊严}}$  
<br>

投奔高级语言？那就丧失了对底层硬件的掌控力；回归底层语言？那就得面对满屏的&和*  

$\color{#008000}{\text{——我试图选择，但也害怕失去...}}$  

于是只能用Python列表推导做数据清洗，用C指针读写传感器缓冲区，用js Proxy写响应式站点，用java 写高并发微服务，用Lua写游戏mod...  
多个世界观之间反复横跳，每一步都可能踩空;上一门语言里的直觉，在下一门语言里可能就是致命错误  

$\color{#008000}{\text{——这些成本从未被算进“技术债”，反而被美其名曰“技术栈”}}$

# AXION不止用于编程，甚至初衷都与编程无关  

#### AXION一开始的目标人群，根本不是开发者，而是产品经理  
产品经理行业长期缺乏标准，需求文档的就是重灾区  
明明脑海里有完整的设计思路，但一到写文档就发现逻辑怎么都写不清楚  

<br>

 $\color{#008000}{\text{——恕我直言，这套计算机专业的必修理论有50\\%是逻辑错误且有误导性的，30\\%是正确的废话，有价值的部分不超过20\\%}}$ 
 
 
靠各种鱼龙混杂的PM社区？   
 $\color{#008000}{\text{——一个个谈天说地，实则一群上班摸鱼er分享那些几乎无法被称之为方法论的经验动态}}$  
 
 
靠自己多年经验潜心摸索总结一套自己的文档规范？  
$\color{#008000}{\text{——我不是没努力过，改了十多版方案都未获得满意的成果（总会遇到无法解释的新问题）}}$

$\color{#008000}{\text{——产品经理这行业那么臭，这些培训机构背大锅：}}$ 
$\color{#008000}{\text{以为原型规范就是产品（画图工），头头是道却不产生实际价值（伪专家），甚至不如《系统分析与设计》那20\\%}}$

实际上答案已经很明确了....  
$\color{#008000}{\text{像程序员那样，一门能真正【能描述任何设计逻辑的产品语言】才是唯一出路 ——这才是AXION真正初衷}}$

# 本文档按 先Tutorial 后Documentation 进行组织
### Tutorial 教程
这个Turorial并不是上来就教你如何写代码  
而是从0开始，带着你分析与推理，不断重复“发现问题->分析原因->解决问题”这个过程  
虽无法100%复盘AXION的设计过程，但也会详细解释在关键节点的决策依据  
<br>
如同一次次的 add 、commit、push  
你会清晰感受到自己一步步对传统编程进行全方位的颠覆与重构、重新审视世界并一步步升华自己的认知    
是一个具有路径感、推理感、叙事感的过程

相当于整合了全部commit后的最终release
