【解释型句柄】完全是编译期被处理掉的静态逻辑，运行时0成本，但也意味着它一般不支持动态修改（至少是不建议）

b ::  x

-- 一般默认会警告，但具体取决于规范

技术层面上说是可以支持【动态解释】的，其本身不会直接导致编译错误

因为说到底编译期在读到【b :: x】时，就跟首次读到【b :: a】一样，把从符号表里把x的offset写到b里即可（覆盖掉原本存的 a的offset）

在此之后 b和x 公用同一个内存

但AXION默认禁止【动态解释】，【动态解释】必须要在特定规范下进行

这里涉及到的问题太多了：作用域、编译型 or 解释型、就算是解释型是否要重新编译函数、静态or动态、全局or局部、字面量\表达式和对象的行为不同......

这里不详细展开，具体见Documentation

总之绝大多数时候都建议认为【解释型句柄】必须是静态、不可修改的 —— 这已经涵盖了绝大多数需求了
