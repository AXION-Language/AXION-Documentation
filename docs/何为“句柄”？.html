什么才算句柄？

-- 不用去试图总结“句柄必须是静态的、唯一的、稳定的、编译器直接识别的...”之类的特征——特征是举不完的，只会把简单问题复杂化（要想证明它是对的，你就必须把所有特征都遍历一遍）

-- 也不用从写法形态上区分，现在有a，a[2]，a.x .....未来也难保会有新的书写形态

--  直接从“句柄的产生”来思考就行了

不存在定义过程，更没有句柄

你只是单纯地这个人【取名】—— 只是往它的姓名字段里填入"小明"这个数据，改的是对象本身的状态


所以当你说“小明”这个词的时候，只会被理解为是 getObjectByName("小明") ，这只是个查询过程

小明可能会改名，但a永远是a

不存在定义过程，而只有判断、查询的过程 (顺着你指的方向，看看终点指的是谁)

【句柄】必须是在定义过程中产生——所谓“定义”，就是“将句柄 与 对象 链接起来”的过程

没有定义过程，就一定不存在【句柄】，更不存在【句柄类型】（实例型、指针型、解释型....），进而也就不存在【句柄属性】

现在，我们能更深刻的回答之前的问题了——那为什么不像传统编程那样直接叫“变量”？

-- 之后我们将在【AXION 类型系统】学到更底层的架构哲学：

本质上 A 是一个 和 class Person 等价的 Type，都是对内部的包装

即A本身就是一种Type，只是不同于class那样有复数个实例，A就只负责单例

传统编程里的【变量】：只是在强调一个【可变的对象】，本质还是【对象】

AXION的【句柄】：是对【对象】的进一步封装，可在对象之外叠加额外属性

结论

A的对象属性 = 对象属性

--更简单的记法：

旧定义：与对象相关的一切特性与关系

新定义：与对象相关的一切特性与关系，都可以用属性来存
