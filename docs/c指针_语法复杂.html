单纯语法复杂并非阻碍，只要用的多总归能熟练，但指针的复杂度远远不止于此..........

取址、解引用 是两个符号，且左右语义不同

int a = 10;      // a 本身就是值

int* p = &a;   // *在左边，表示定义p是int类型的指针;   &取地址


printf("%d\n", a);   // 输出10 

printf("%d\n", *p);  // 输出10 ，*在右边，表示解引用

printf("%d\n", p);   // 输出一串地址0x7FF0...，总之不是 10）

struct Point {

    int x;

    int y;

};


struct Point a = {1,1};


printf("%d\n", a.x);     //  1

printf("%d\n", a);   // ❌ 编译错误，结构体的变量名不是地址

printf("%p\n", &a);   // 需要&手动取地址


struct Point* ptr = &p; // 先用*标记是Point的指针，再用&取地址


printf("%d\n", (*ptr).x); //  1（先解引用，再用. ）

printf("%d\n", ptr->x);   //  1（箭头简化，等价上面）

printf("%p\n", ptr);      // 0x1000....（不需要解引用）

结构体的访问则更复杂，即便语法上提供“->”简化书写

1、由于取址、解引用是两个符号，所以导致我经常把*和&两个符号搞混，总是把&当成解引用——相信这不止我一个如此

2、一段时间不用就会分不清应该写int*  a 还是写  *int a  还是 int *a  还是 int &a .....

3、容易和乘法*  、逻辑与&&、位运算& .....混在一起

4、再牵涉到函数调用与嵌套、多级指针、类型签名强制转型如void** 那更是看的眼花缭乱

.....—— 所谓的“行业壁垒”一半都源自于语法带来的无意义的复杂度
