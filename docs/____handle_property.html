排除那些函数特性（之后会在【函数】章节单独学习），这里仅聚焦于【句柄属性】的特性：

上例中，a和b的对象类型都是int，所以二者的对象属性完全相同（都是空）

但即便都是int，也并不意味着a与b的属性完全相同

因为 a b的环境、用法 .... 也可能存在不同，这个差异是由 a 与 b 这两个句柄本身带来的，所以叫【句柄属性】

【句柄属性】 可以在 【对象类型】之外，为不同对象赋予个体差异

--目前任何传统编程都无法实现这个建模，而实际上这是人类非常普通的世界观

--因为传统编程的里只有【变量与类型】，如果a与b类型相同，那a与b的字段就一定完全相同，没有个体差异  (这里只是以int举例，实际换成 new Person()结果是一样的)

利用【句柄属性】，我们能集中管理原本分散、零碎的对象，对象之间的关系更加明确，更利于进行模块化的维护

上例只是个简单例子，实际开发中一个上下文内的变量、方法非常多

解析

【句柄上下文】：payload 和 句柄属性 组成的部分

1、避免变量名冲突，例如多个变量都有ver字段的情况

2、【句柄上下文】是一种【结构型上下文】，这意味着不用担心定义顺序，之前定义的函数可以正常访问后面定义的变量

--在传统编程里，正常情况下，如果在一个【过程型上下文】内（例如函数内）

前面定义的函数 f 是无法直接访问之后定义的变量 a 的，会提示a undefined，除非再额外增加类似于“变量提前”的机制额外处理

--不会破坏【类型签名】
