Payload 一词的由来——取自物流工程、成本核算、火箭科学、网络协议...这些专业领域中的说法

总重量/总量中，那个真正有用的部分，或者说核心价值，如 10 吨货物

其余部分都是“为了让它能干活而付出的代价”，如燃料、包装箱、卡车、司机...等

在一趟运输业务中，我的根本目的“不是把卡车开到目的地”，而是“交付那10吨货物”


一个传输或承载单元中，真正携带的业务数据或完成核心功能的部分，如用户信息、订单数据

其余部分都是“为了让了传输、解析它而付出的代价”，如协议头、校验码、元数据...等


总之，去掉所有“包装、运输、协议...”的成本，剩下的那个“唯一目的”就是Payload

有效载荷 Payload

一切【与Payload相关的对象】，都是【Payload的属性】，广义上相当于Feature

反过来理解这个定义，就可以得到【属性的用途与价值】—— 用【属性】代表一切与【Payload有关的对象】

例如:保存状态、存储额外信息、为Payload的使用提供代理与支持、建立与其他对象的关系网络....

不同于JS那种只有属性的、也不同于Java只有成员的

AXION这两者同时存在，属性Property是用来描述对象Payload的——假设1个Payload有3个Property，那么此时总共就是4个对象！

注意：AXION里 属性Property 与 对象Payload 是两个绝对独立、同时存在的概念
