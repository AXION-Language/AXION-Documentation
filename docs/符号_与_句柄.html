符号 与 句柄

是AXION里具有奠基意义的设计哲学，是对人类基本世界观的抽象

上文已经或多或少涉及到，这个模块花三个章节做个系统性的讲解

这里我们引入了一个新概念：句柄 (Handle)

 "句柄" 这个命名借鉴自windows平台，是一个用来标识对象或者项目的“无符号整数”

那为什么不直接叫“符号”？非得搞出个“句柄”的概念？

正如“C语言地址与指针”的关系：

指针本质上就是个地址，但是 int* 解引用能得到一个int，所以我们人为给它包装了一层“指针”概念


类比“符号 与 句柄”也是同理

a、b、c....在客观上只是符号，纯粹的图形本身没任何语义

但我们主观上需要它承担 "访问对象" 的职责，所以给它一个新概念叫“句柄(Handle)”


再例如“沙盘中的 🚩 与 军队”

🚩本身可能是塑料/木头做的，但显然我们在意的根本不是🚩本身是塑料还是木头

🚩在沙盘里只是一个【象征物】，我在意的是它所象征的军队


——这是为了强调职能 (代表什么)，而不是强调【象征物】本身是什么

窗口句柄 HWND hWnd = 00000000001208A4  

文件句柄 HANDLE hFile = 0x00000000000000B4

进程句柄 HANDLE hProcess = 0x00000000000000F0

闹麻了，那为什么不像传统编程那样直接叫“变量”？

那么，将其抽象一下——

本质上就是通过"身份证、手机号...或是符号、整数..." 之类【象征物】来访问特定的资源，有这种价值的【象征物】就称为【句柄】

这并非故弄玄虚


而是传统编程【变量】的概念过于狭隘

1、只能用来表示开始 a=1 之后 a=2 这种单纯的数值改变

2、与内存强耦合，一个变量就对应底层一块内存数据


而在AXION里，【句柄】功能异常强大，远远超出单纯的【符号、变量、值】这些概念范畴

在之前指针问题里，句柄已经无可取代，而在之后很快会学到的【Payload-Property建模理论里】你会更加惊叹于它的价值
