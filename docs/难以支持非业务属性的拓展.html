抛开一切语言自动添加的字段，我开发者自己也可能会主动添加字段来满足

以js为例，我们现在有个需求：跟踪person对象的修改次数，保存在名为 ver 的变量里

我自己心里知道，这个ver不是个人信息，最终不会写到数据库里，只是我编程时用来管理数据的一种临时对象，例如脏值检查、快速判断是否被修改过等目的

而至于这个修改方法，我可以写个update(){...ver++...}，为了避免干扰，我还可以把它放到链上

而ver 是跟随每个数据的，所以只能放到 实例 内部

class Person {

    constructor(name, age, city) {

        this.name = name;

        this.age = age;

        this.city = city;

        this.ver = 0

    }

}

Person.prototype.update=function(){this.ver++}


let person = new Person("张三", 25, "北京");

person.update()

name：张三

age：25

city：“北京”

ver：0

[[prototype]]: Person.prototype

...

Person.prototype

我真正希望的是：

1、{name、age、city}作为核心业务数据，需保存进数据库里

2、而ver字段仅仅是软件运行时的一种跟踪数据的手段，而不是我的业务数据，但在传统OOP语言里，我只能将其和业务数据混杂在一起

非业务数据 会 污染核心业务数据

然后就又回到了原点：

打印对象时，我得手动剔除ver

对象拷贝时，我得手动剔除ver

网络传输时，我得手动剔除ver

写数据库时，我得手动剔除ver

....

总之想做任何针对a的访问时，这个ver都会永永远远干扰我，它始终和我的业务数据混在一起了

-- 当然，任何一个编程语言都可以通过各种设计模式，拐弯抹角的封装子类、封装代理来处理，但终究很麻烦，这是一种妥协，而不是我真正想表达的意思

-- 而实际上从一开始， 我就已经知道了{name age city}是我要的对象，ver只是这个数据对象的属性，但传统OOP根本不支持这种建模

——说到底，传统编程压根就没真正搞清楚什么是对象、什么是属性这一基本问题
