Q: 一个符号能同时支持两个语义？这是如何做到的？

A: 利用前后位置来区分

容易和乘法*、逻辑与&&、位运算&....搞混

   int a = 10;     

~int addr = ~a  

 

addr~ = addr~ + 5 

print a

print addr~  


addr = addr+5

addrrint addr

抛开指针->这种上层语法不谈，AXION本身也是支持对底层“内存地址”的定义与操控，只是在从语法、抽象程度上对传统编程进行了优化

虽说只是看似小小的变化，但在世界观、语义层面却是一大步，能减轻不少编程负担

-- addr的解引用+5

 --addr所引用的对象 + 5，也就是a+5，所以是15    

符号简单、逻辑对称、 符合直觉

-- 类型签名里用* ，但右值又得用&，很容易搞混搞反（反正我自己每隔一段时间就得搞混一次）

 --addr本身也直接进行地址运算，上文也说过：AXION的指针运算是与类型解耦的，所以不会像C系列那样自动×size）

回顾C 和 C++的写法

AXION里只有一个引用符~，即可同时承载“取引用”“解引用”两个逻辑

-- addr = a的引用，即0x1000；只有一个符号~ ，优雅

任何实例

~a

a的引用

仅地址(ADDR)可用

a~

a 所引用的对象、a的解引用；


例如 ~int addr=~a  ，现在addr= a的引用 

那么只需“两边同时解引用”就能获得  addr~ = a 的语义

(addr的解引用就是a、addr所引用的对象就是a) 

方法论：

抽象了【引用】这个概念为“地址——对象”这样的两点一线模型

此时，【取引用、解引用】就变成了“同一个事实的两个切面”——将两种语义统一进同一个意识形态里

因此，“连线 + 某一端”即可表示两种语义
