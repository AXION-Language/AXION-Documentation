案例对比：同一个需求，“传统编程多级指针” vs  “AXION单级指针”

void alloc(void** ptr, int size) {

    *ptr = malloc(size); 

}


int* buf = NULL;

alloc((void**)&buf, 4);



*buf = 10

print *buf

举例传统编程里，比较典型的“二级指针”的场景

然而同样的功能逻辑，在AXION里，无论是思路、还是写法、还是对buf对象的使用.....都更简单，一级指针即可完成

void alloc(~ addr-> , int size) {

    addr = malloc(size); 

}


int buf -> NULL

alloc(buf_ADDR, 4);


buf = 10

print buf

--buf是个指针，我们的目的是：在堆上申请分配一段内存，将堆内存地址填入buf——即修改buf本身

-- 传入buf的地址(因为我们要让alloc修改它) + 所需申请的内存量4字节

--为了匹配参数ptr的类型签名，这里需要手动转型成void**

-- 需要用ptr来修改源对象，所以ptr得是个指针

-- 但因为参数buf又是一个指针，所以最终导致ptr得是个二级指针，所以签名是void** ptr

-- 需手动解引用，输出10

-- 需手动解引用，来为buf指向的堆内存赋值

-- buf的语义就是最终的数据对象，具体指向哪块内存由buf_ADDR决定

-- 直接把buf_ADDR 传给alloc让它帮我改，无需手动&取地址、**解引用、再转型成void**  这一大堆乱七八糟的事

为了能通过addr直接改buf_ADDR，所以addr得是个地址类型的指针，调用时相当于 addr -> buf_ADDR——单纯的地址运算，根本无需依赖void**这些奇怪的类型

所以改addr就是改buf_addr

-- 直接写buf就行，无需手动解引用

所以虽然AXION支持多级指针，但实际应用场景很少，大部分时候单级指针足够了

多级指针的场景更多时候只是为了修改地址本身（例如动态的内存分配），而不是修改目标数据

而在这种需求场下，传统编程的多级指针则能被AXION降级为单级指针，进一步降低了复杂度
