针对指针语法过于复杂的问题，后续不少语言都有了一定优化

例如C++提出了“引用/别名”的机制

int a = 10;


// 1. C   用*表示指针

int* p = &a;

*p = 100;


// 2. C++  用&表示引用

int& r = a;

r = 100;


// 混着用也行

int* p2 = &r;   // 引用可以取地址

int& r2 = *p;   // 指针可以解引用后绑定给引用

#include <stdio.h>


int a = 10;


// C 风格：指针，需要手动解引用

void change_ptr(int* p) {

    *p = 100;        // 必须用 *

}


// C++ 风格：引用，自动解引用

void change_ref(int& r) {

    r = 100;         // 直接赋值，相当于 *p = 100

}


int main() {

    //当我想要修改a时

    change_ptr(&a);   // C需要手动用&取地址

    printf("%d\n", a);  // 100

   

    change_ref(a);    // C++可直接传变量名

    printf("%d\n", a);  // 100

   

    return 0;

}

在函数调用中，也省去了不少写&和*的麻烦：

int a = 10, b = 20;

int& r = a;  // r 是 a 的引用，底层仍基于指针实现（内存里保存的是 &a）

r = b;      

我永远无法将r的引用从a改到b，这相当于直接缺失了一部分语义功能

在C++里，r的语义已经被固定死了，所以r=b一定是修改a；

歧义

乍一看是不是大功告成，近乎完美? 但实际上这反而是更糟糕的设计....

首先排除“对象的引用”=“指针”这件事

因为一旦这样认为，r就必须是指针，那就绝对不可以用 r=20 来修改原值a（这会被视为修改r指针的值）——每个概念都必须有唯一且明确的语义，不能互相串


现实中真的有像C++所谓“引用对象”这样的意象吗？

我有想过“文件的快捷方式”、编辑器里的“引用组件”，但都感觉不太像，毕竟它们有自己独立的属性——快捷方式有自己的文件属性，引用组件有自己的位置大小等属性

而 int& 则是完完全全的重定向，但除了能像普通int那样参与运算，还会有其他特殊性吗？——至少从世界观上我无法预测，只能去翻阅C++的开发规范来被动接受规则

想来想去，感觉还不如指针简单呢，指针可以类比于身份证、手机号、门牌号...它是实实在在的物理实体，逻辑非常干净

int& r = a

总之，C++看似给了一个不错的解决方案，但结果却是“拆东墙补西墙”

它的世界观是混乱的，根本没有地定义清楚“引用究竟是怎样的一种意识形态”

如果r引用a的语义并没有在“编译时”就被彻底“消化”掉：正如预编译宏那样，从源码层面直接把r全都替换为b，运行时r不占内存

那么“r的引用，一经定义，不可修改”就是合理的

“不能修改r的引用”这件事并不是因为编译时把“int& r=a”的语义处理掉而被迫固定，而纯粹是语言设计者的武断

但实际上，运行时C++仍然会给r分配内存，它是实实在在存在的“指针对象”，理论上r的内存数据是可以改的

-- C++引用底层就是用指针来实现的

在这种情况下，“不允许修改引用”完全是C++设计者的个人意愿——因为设计者没有找到一个合理的语义来描述这个逻辑，所以只能强行锁定

实际上，C++的引用还有2种写法，第2种相对更合理，但又引入了新的歧义

从“不破坏类型签名”的角度来看，第二种方案相对更好，但问题是又带来了“&”的歧义

int&  r  = a  "引用是类型的一部分"，强调类型是 int&    

int  &r  = a   "引用是变量的一部分"，强调 &r 整体是a

// 声明中的 & → 引用
