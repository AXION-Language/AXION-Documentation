Payload

属性 Property

Payload是属性的持有者，一切属性都是用来描述、且依附于 payload 的

Payload - Property

类似于“人 vs 父亲”的关系，"人"是固有特性，"父亲"强调了亲属关系

Payload同样是在强调“Property的所有者”这层主人身份


在AXION里任何属性也都是对象（万物平等）

若全都说【对象】的话，思考问题时，很容易又退化成传统编程那套纯靠变量名(.body .value) 区分的“扁平化”模型里了

总之现在起，一旦说到Payload，你就应该知道 ——

它是“承担、发挥核心价值”的那个内核，它是属性Property的持有者

Payload (有效载荷 )

Payload 一词的由来

Payload能保留【主从关系】的逻辑, 不会丢失精度

这样做的原因是：

参考了物流工程、成本核算、网络协议...这些领域中的说法——

总重量/总量中，那个真正有用的部分，或者说核心价值，如 10 吨货物

其余部分都是“为了让它能干活而付出的代价”，如燃料、包装箱、卡车、司机...等

在一趟运输业务中，我的根本目的“不是把卡车开到目的地”，而是“交付那10吨货物”


一个传输或承载单元中，真正携带的业务数据或完成核心功能的部分，如用户信息、订单数据

其余部分都是“为了让了传输、解析它而付出的代价”，如协议头、校验码、元数据...等

——去掉所有“包装、运输、协议...”的成本，剩下的那个“根本目的、唯一价值”就是Payload

-- 暂时简单理解，就是单纯的把之前的Object 改成 Payload

-- 一般建议直接用英文 Payload，因为中文里实在很难找到更合适的翻译了
