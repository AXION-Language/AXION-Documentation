传统“预编译宏”是预编译阶段纯粹的文本替换

它们确实很像，所以 C 开发者在刚接触到AXION的【解释符】时，很容易和【预编译宏#define】联系在一起，这无可厚非

—— 但实际上，【AXION解释型句柄】和【C预编译宏】的设计理念、实现原理、能力范围 的差异都很大

C/C++的宏：

#define PI 3.14159

#define MAX 100


float area = PI * r * r;  // 展开为: float area = 3.14159 * r * r;

int arr[MAX];              // 展开为: int arr[100];

#define b a


int a=10

print("%d",b)       // 展开为: print("%d",a)

C/C++ 预编译宏

#define c *c_ptr


int a = 10;

int* c_ptr = &a;


printf("%d",c+5)

它凌驾于一切语言契约，无视任何运算符、作用域、类型系统.......

仅仅是纯文本的查找与替换（哪怕是一串毫无意义的乱码符号）

看似在编程，实则只是 文本批量脚本，正在侵入式地污染编程逻辑

完整写法是：

--手动定义一个int的引用，存储a的引用

-- 手动把c解释为 #addr的解引用

-- 会被编译器理解为  c#addr~  +  5 ，输出15

-- 15

10

0x1000

0x1004

b

符号

运行时 内存

-- 画成虚线是想表示：编译器并不会直接静态地把 b 指向 10 这个数据

而是会根据 b#addr 在运行时动态计算

现在b#addr存的是0x1000的地址，所以通过b 即可直接访问10这个数据

--定义一个宏，把c替换为  *c_ptr

--定义c_ptr是int指针，存储a的地址

-- c 会被替换为 *c_ptr，输出15

即，从技术上说只需【实例型句柄 : 】 和 【解释型句柄 ::】就够了

【指针型句柄 ->】不是必要的

--语法糖‌（Syntactic Sugar）

指编程语言中，为了提升代码可读性或简洁性而设计的便捷写法

其底层逻辑不变、不提供新功能，但能让代码更好写、更好看
