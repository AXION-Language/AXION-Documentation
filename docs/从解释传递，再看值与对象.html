编译器自身没问题：

因为编译器会维护一个符号表

在读到“ b :: a”的瞬间，只要去查a的符号表，就知道a是个值了；当场就可以把a里的10复制进b自己的符号表里——编译器可以快速检索整个【解释链】

语言逻辑没有错、编译器也没错，只是“用户体验”不太好

但开发者就不方便了：

开发者一般不会在某张纸条上维护一张符号表，记录b当前的值具体是啥

开发者眼里只能看到  int b :: a 这句定义，无法直观知道a是值还是对象，只能从头翻代码
