句柄属性

概念：

仅依附于句柄、绑定于句柄的属性，与具体对象类型无关

✔️ 句柄属性、句柄级属性：完整含义是【句柄级别的属性】，或是【绑定于句柄的属性】—— 仍然是对象a的属性，只是这些属性依附于句柄而存在

❌️ 句柄的属性：payload就变成了句柄a，这毫无意义

int b: 20

a和b本身对象类型都是int

int本身就是一个纯数字，没必要有属性；

又或者说，就算int有属性，那a和b由于都是int，所以属性是相同

不受【对象类型】束缚，自由设计对象差异

但是，这并不意味着a和b的属性相同，因为我们可以给ab赋予不同的【句柄属性】

这取决于你对a和b两个数据用法的不同，例如同样是int，a是 money， b是score，主观用途不同，所以属性不同

——总之在AXION里，你可以无视对象类型，给任何一个【对象】，添加任意【句柄属性】，这是完全自由的

-- 这是任何传统编程都无法实现的功能：传统编程里，类型一致=> 行为必定一致，没有差异

句柄上下文

1、避免变量名冲突

例如多个变量都有ver字段的情况，你无需用a_ver 、b_ver 这种变量名强行区分

直接在ab各自的句柄属性里定义ver就行了


2、【句柄上下文】是一种【状态型上下文】，所以不用担心定义顺序，之前定义的函数可以正常访问后面定义的变量

而在传统编程里

在一个【过程型上下文（如函数）】内，前面定义的函数 f 无法直接访问之后定义的变量 a 的，会提示“a尚未定义”

除非像JS那样再额外引入“变量提升”与“暂时性死区”2个机制才可以

#fn update(){ this=this+5; ver++}

4、句柄上下文内，将严格遵守payload本身的Type

#fn setV(int v){ this=v; print "触发setV代理"}

int a : 10


a= a+5

句柄上下文内

将严格遵守payload本身的【对象类型】，例如这里a的type是int

而a#setV是定义在a上的【句柄属性】，与具体对象类型无关，所以this = v 不会产生任何副作用（副作用：Proxy内部又触发自己导致无限递归爆栈）

-- 这是一个Proxy，将在用 a= 修改值时触发

而在传统编程里，在Proxy中避免这种递归问题是非常麻烦的

let a = {

    _value: 10,

    set value(v) { this._value = v;}

}

a.value = a.value + 5

a.value = a._value + 5
